# 2026-05-26 ESP-SR 2.4.6 Full-Duplex AEC Baseline

## Scope

This records the 2.0 bottom-layer alignment pass before recognition-quality tuning resumes.

The goal is to make the firmware depend on Espressif's official full-duplex AEC/AFE path first. Acoustic tuning can be repeated later after the enclosure changes the echo path.

## Confirmed

- The firmware dependency is now pinned to `espressif/esp-sr: 2.4.6`.
- `idf.py fullclean` removed the previous build and managed component cache.
- The clean build resolved `espressif/esp-sr (2.4.6)` from ESP Component Registry.
- The build component path is `D:/esp32/esp32idf-robot/managed_components/espressif__esp-sr`, not ADF's vendored `components/esp-sr`.
- Official full-duplex AEC was introduced in ESP-SR `2.4.3`; this baseline is above that minimum.
- The local 2.4.6 changelog notes `2.4.5` fixed an ESP32-S3 coexistence issue between `esp-dl` and `esp-sr`, while `2.4.6` removes a redundant heap check.

## Firmware Contract

Changed file:

- `esp32idf-robot/main/afe_capture.c`
- `esp32idf-robot/main/idf_component.yml`
- `esp32idf-robot/dependencies.lock`

The AFE startup now enforces the full-duplex assumptions explicitly:

- `AFE_TYPE_FD`
- `AEC_MODE_FD_LOW_COST` by default
- `AEC_MODE_FD_HIGH_PERF` remains guarded by `ROBOT_ALLOW_EXPERIMENTAL_AEC_HIGH_PERF`
- playback reference channel is required
- `output_playback_channel = false`, so AFE fetch output cannot include speaker reference audio for Doubao upload
- `fixed_output_channel = true`, so the upload path stays fixed to microphone output instead of dynamic WakeNet/VAD channel selection
- `fixed_first_channel = true`, matching the single selected mic path used by this Korvo-2 tuning
- noise suppression stays enabled on the FD path
- startup validation fails fast if `afe_config_check()` clears either fixed-output flag

The boot log now prints a compact FD-AEC contract:

- minimum ESP-SR version expected for FD AEC
- pinned ESP-SR version
- input format and parsed mic/reference counts
- checked AFE/AEC modes
- filter length and NLP level
- fixed output and playback-reference-output flags

## Current Decision

Keep `RNNM` as the Korvo-2 default for now, because previous raw TDM diagnostics showed:

- `ch0` is the playback reference
- `ch3` is the cleaner microphone channel

The official input-format rule is still respected: `R` is reference, `M` is microphone, and `N` is unused. The physical channel order is board-path specific and can be revalidated after the enclosure is installed.
